## Bias and Variance

- Bias = training error (with plenty of data) 
	- the error rate of your algorithm on your training set when you have a very large training set
- Variance = test error − training error
	- how much worse you do on the test set compared to the training set in this setting.

| Training Error | Test Error | Bias | Variance | Diagonistic                                            |
| -------------- | ---------- | ---- | -------- | ------------------------------------------------------ |
| 1%             | 11%        | 1%   | 10%      | **Overfitting.** Fits train well, fails to generalize. |
| 15%            | 16%        | 15%  | 1%       | **Underfitting.** Poor fit, but train and test match.  |
| 15%            | 30%        | 15%  | 15%      | **Both high.** Poor fit and poor generalization.       |

**Tradeoff**

- Many fixes lower one and raise the other
- A well-suited architecture can improve both, but it's hard to find

**Reduce bias**

- Bigger model
	- More capacity (layers, units, parameters) lets it fit more complex patterns in the training data.
- Less or no regularization
	- Regularization holds the model back, so relaxing it lets the model fit the training set more closely.
- More data does _not_ fix bias
	- A model that is too simple underfits no matter how many examples it sees.

**Reduce variance**

- More data (simplest and most reliable, if you can afford the compute)
	- More examples make it harder to memorize noise, so the model generalizes better
- Regularization (L1, L2, dropout): lowers variance, raises bias
	- It penalizes complexity, so the model fits noise less, at the cost of a slightly worse fit to the training set
- Early stopping: same effect as regularization
	- Stopping before the model fully fits the training set keeps it from memorizing noise, like a complexity limit 
- Feature selection: helps mostly when data is small
	- Fewer irrelevant features mean fewer ways to overfit. With lots of data the model learns to ignore bad features itself
- Smaller model: use with caution. Prefer regularization, and shrink the model only to save compute.

## Learning Curves

- Useful for diagnosing bias and variance.
- A learning curve plots your dev set error against the number of training examples.
- As the training set size increases, the dev set error should decrease.

```python
from sklearn.model_selection import learning_curve

def plot_learning_curve(model, X, y, title="Learning curve",
                        desired_error=None, cv=5, ax=None):
    """Plots train/dev error (1 - accuracy) as the training set grows."""
    sizes, train_scores, dev_scores = learning_curve(
        model, X, y, cv=cv, scoring="accuracy",
        train_sizes=np.linspace(0.05, 1.0, 10), shuffle=True, random_state=0,
    )
    train_err = 1 - train_scores.mean(axis=1)
    dev_err = 1 - dev_scores.mean(axis=1)
 
    ax = ax or plt.gca()
    ax.plot(sizes, train_err, "o-", label="Training error")
    ax.plot(sizes, dev_err, "o-", label="Dev error")
    if desired_error is not None:
        ax.axhline(desired_error, color="gray", ls="--", label="Desired error")
    ax.set_xlabel("Training set size")
    ax.set_ylabel("Error")
    ax.set_title(title)
    ax.set_ylim(0, None)
    ax.legend()
    ax.grid(alpha=0.3)
    return ax
```
